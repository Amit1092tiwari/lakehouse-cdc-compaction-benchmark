---

## ⚡ The Production Problem: Small-File Sprawl

When streaming CDC events (INSERT, UPDATE, DELETE mutations) into cloud object stores (Amazon S3, Google Cloud Storage, Azure Blob), naive streaming flushes write hundreds of tiny 15KB–45KB files every minute.

```text
[ Streaming CDC Ingress ] ──> [ Naive Micro-Batches ] ──> [ Thousands of Small Slices ]
                                                                     │
                                      ┌──────────────────────────────┴──────────────────────────────┐
                                      ▼                                                             ▼
                       Object Store Prefix LIST Bottlenecks                       Query Engines Scan Thousands of Handles
                       (High metadata latency / S3 503 SlowDown)                  (Severe memory thrashing & degraded SLAs)
```

### The Architectural Solution: Merge-on-Read + Asynchronous Compaction
Decouple streaming delta ingestion from Parquet base file compaction. Micro-batches append rapidly to lightweight row-oriented delta logs, while background compactors consolidate slices into dense columnar base files (128MB target size).

```text
[ CDC Mutations ] ──> [ Delta Log Slices ] ──> [ Asynchronous Compactor ] ──> [ 128MB Columnar Base Files ]
                                                                                      │
                                                                                      ▼
                                                                        [ Fast Vectorized Query Scan ]
```

## 🔭 Observability & OpenTelemetry Telemetry Integration

SigNoz and modern OpenTelemetry architectures monitor distributed data systems by treating storage compactions, metadata lists, and vectorized table scans as first-class observable events.

The benchmark runner instruments each stage and exports metrics according to standard OpenTelemetry (OTLP) resource semantics:

### Telemetry Metrics Emitted
* **`lakehouse.file_handles.count` (Gauge)**: Tracks the number of small object handles within the partition prefix. An unchecked exponential increase signals compaction starvation.
* **`lakehouse.compaction.duration_ms` (Histogram)**: Measures the execution wall-clock time required for background Merge-on-Read consolidation passes.
* **`lakehouse.query.latency_ms` (Histogram)**: Quantifies query engine aggregation scan speed (measuring query degradation under uncompacted small files vs compacted base files).
* **`lakehouse.metadata_scan.latency_ms` (Histogram)**: Tracks directory traversal / S3 `LIST` metadata latency.

### OpenTelemetry OTLP Exporter Configuration
Benchmarks automatically generate standard OTLP JSON telemetry in `data_lake/otlp_metrics.json`, ready to be ingested directly into any OTLP collector (e.g., SigNoz or Jaeger):

```python
# OpenTelemetry SDK Metric Export to SigNoz OTLP Collector
from opentelemetry import metrics
from opentelemetry.exporter.otlp.proto.grpc.metric_exporter import OTLPMetricExporter
from opentelemetry.sdk.metrics import MeterProvider
from opentelemetry.sdk.metrics.export import PeriodicExportingMetricReader

exporter = OTLPMetricExporter(endpoint="localhost:4317", insecure=True)
reader = PeriodicExportingMetricReader(exporter, export_interval_millis=5000)
provider = MeterProvider(metric_readers=[reader])
metrics.set_meter_provider(provider)

meter = metrics.get_meter("lakehouse.compaction.telemetry")
file_counter = meter.create_gauge("lakehouse.file_handles.count", unit="1")
compaction_timer = meter.create_histogram("lakehouse.compaction.duration_ms", unit="ms")
```

## 💻 Prerequisites & Container Host Ports

Before executing the benchmark, ensure your system satisfies the following prerequisites:

* **Container Tooling:** Docker Engine 24+ and Docker Compose v2+
* **Local Python Runtime (if running without Docker):** Python 3.10, 3.11, or 3.12 (`pip install -r requirements.txt`)
* **Hardware Requirements:** 1 vCPU and 2GB available host RAM (runs easily on laptops, WSL2, or CI runners)

### Container Host Port Mappings
When running via Docker Compose, services are mapped to the following local ports:

| Service | Container Port | Host Port Mapping | Description & Credentials |
| :--- | :--- | :--- | :--- |
| **MinIO S3 API** | `9000` | `http://localhost:9000` | S3-compatible object storage API (`minioadmin` / `minioadminpassword`) |
| **MinIO Web Console** | `9001` | `http://localhost:9001` | Interactive UI to inspect object store prefixes and data slices |
| **SigNoz / OTLP gRPC** | `4317` | `http://localhost:4317` | Standard OpenTelemetry gRPC metrics and trace ingress |
| **SigNoz / OTLP HTTP** | `4318` | `http://localhost:4318` | Standard OpenTelemetry HTTP metrics and trace ingress |

## 🚀 Quickstart: Run in 1 Command

### Option 1: Docker Compose (Full Environment with MinIO S3)
To spin up the local S3-compatible MinIO object store and the automated benchmark runner:

```bash
docker compose up --build
```

### Option 2: Run Locally (Linux / macOS / WSL2)
```bash
# Install dependencies
pip install -r requirements.txt

# Run the benchmark harness
./run_lab.sh
```

### Option 3: Run Locally (Windows PowerShell)
```powershell
.\run_lab.ps1
```

## ⚙️ Production Configuration Directives

### Apache Hudi (`hoodie.properties`)
```properties
# Enable Merge-on-Read storage type
hoodie.datasource.write.table.type=MERGE_ON_READ

# Decouple inline compaction from critical write path
hoodie.compact.inline=false
hoodie.compact.schedule.inline=true
hoodie.compact.inline.max.delta.commits=5

# Target 128MB columnar Parquet base file size
hoodie.parquet.max.file.size=134217728
hoodie.parquet.small.file.limit=104857600
```

### Apache Iceberg (`spark-defaults.conf`)
```properties
# Rewrite data files in background maintenance jobs
spark.sql.iceberg.planning.max-data-files-per-split=500
spark.sql.iceberg.planning.split-size=134217728
```
